# Ancilis Demo Walkthrough

> See an AI agent's tool calls intercepted, evaluated against runtime security controls, and visualized in the Platform dashboard in a single guided flow.

## Prerequisites

- Python 3.10+
- Docker Desktop or Docker Engine with `docker compose`
- `curl`
- The SDK repo checked out at `ancilis`
- The Platform repo checked out as a sibling at `../ancilis-one-shot`

If your Platform checkout lives somewhere else, set `ANCILIS_PLATFORM_DIR` before running the demo script.

## Quick Start

From the SDK repo root:

```bash
bash examples/demo/run-all.sh
```

What this command does:

- runs shared preflight checks for Python, `curl`, Docker, and Platform checkout discovery
- creates or reuses `.demo-venv` in the SDK repo
- resets the demo DuckDB evidence store and runs the financial demo agent
- starts the Platform stack with Docker Compose from `./platform`, `../ancilis-one-shot/platform`, or `ANCILIS_PLATFORM_DIR`
- logs into the seeded demo tenant, creates or reuses a workspace-scoped `sdk_direct` integration for the current DuckDB path, and syncs the generated evidence
- opens the dashboard on macOS when `open` is available

The script keeps the Platform stack running until you press `Ctrl+C`.

## Step-by-Step

### Step 1: Prepare the SDK demo environment

From the SDK repo root:

```bash
bash examples/demo/setup.sh

# or manually
python3 -m venv .demo-venv
source .demo-venv/bin/activate
python -m pip install -e ".[dev]"
```

`setup.sh` reuses `.demo-venv` and runs the shared demo preflight checks before installing the SDK and CLI entrypoints.

### Step 2: Run the financial demo agent

```bash
python examples/demo/run.py
```

You should see:

- a framed banner identifying the financial runtime-controls demo
- a tool registry section showing approved, unapproved, and explicitly blocked tools
- a tool-call transcript with 6 evaluated calls, including 4 `ALLOW` and 2 `BLOCK` decisions
- a summary section with overlay activation, AIUC-1 readiness tracking, and evidence totals
- a final line showing the generated DuckDB path under `~/.ancilis/`

The demo responses intentionally include financial, card, and PII patterns so the exposure and overlay logic is visible in the output.

If you want the verbose CLI views after the demo run, use the emitted DuckDB path:

```bash
ancilis status --verbose --config examples/demo/ancilis.yaml --db /path/to/evidence.duckdb
ancilis report generate --format markdown --config examples/demo/ancilis.yaml --db /path/to/evidence.duckdb
```

### Step 3: Start the Platform stack

If your Platform repo is the default sibling checkout:

```bash
docker compose -f ../ancilis-one-shot/platform/docker-compose.yml up --build -d
```

If you prefer to point at a different Platform checkout:

```bash
ANCILIS_PLATFORM_DIR=/absolute/path/to/ancilis-one-shot/platform bash examples/demo/run-all.sh
```

The Platform stack exposes:

- dashboard: `http://localhost:3000`
- backend docs: `http://localhost:8000/docs`

### Step 4: Sync the SDK evidence into the Platform

`run-all.sh` automates this step, but the flow is:

1. log into the demo tenant
2. create or reuse a workspace-scoped `sdk_direct` integration whose name starts with `Finance Demo SDK`
3. bind that integration to the DuckDB file generated by `examples/demo/run.py`
4. trigger a sync so the Platform ingests the demo evidence

Demo credentials:

- organization slug: `ancilis-demo`
- email: `admin@ancilis.demo`
- password: `AncilisDemo123!`

### Step 5: Open the dashboard

Open `http://localhost:3000` and sign in with the demo credentials.

What to look for:

- the `Finance Demo SDK (...)` integration in `Integrations`
- evidence created from the six demo tool calls
- discovered systems and posture changes driven by the synced SDK evidence
- dashboard and evidence views that reflect the same runtime decisions printed by the demo agent

## What Just Happened

1. The financial demo agent executed six mock MCP tool calls through Ancilis middleware.
2. Each tool call was evaluated against the active AKSI controls before the underlying tool response was returned.
3. The declared data classifications activated the `soc2`, `pci-dss`, and `glba` overlays automatically.
4. AIUC-1 certification targets were resolved alongside the baseline controls.
5. Each evaluation was persisted into a SHA-256 hash-chained DuckDB evidence store.
6. The Platform bootstrapped or reused a workspace-scoped `sdk_direct` integration that points directly at that DuckDB file.
7. A sync imported the SDK evidence into the Platform so the dashboard could visualize the resulting posture.

## Troubleshooting

- If `run-all.sh` says it cannot find the Platform checkout, export `ANCILIS_PLATFORM_DIR` to the `platform` directory inside `ancilis-one-shot`.
- If Docker is not running, start Docker Desktop or your local Docker daemon before launching the script.
- If the dashboard is up but the integration shows no evidence, rerun `bash examples/demo/run-all.sh` to regenerate the demo evidence store, recreate or reuse the workspace-scoped integration for the current checkout, and trigger another sync.
- If you want to stop the demo stack manually after using the quick start script, press `Ctrl+C` in the terminal that launched it.
