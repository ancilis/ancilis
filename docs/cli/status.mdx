## Overview

`ancilis status` displays a concise summary of your agent's current compliance posture: active controls, overlay status, evaluation counts, and any flagged deviations. It's the quickest way to check agent health during development without the CI exit-code semantics of `ancilis scan`.

```bash
ancilis status [OPTIONS]
```

## Flags

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--verbose`, `-v` | flag | `false` | Show per-control breakdown with evaluation details |
| `--config` | string | auto-detect | Path to `ancilis.yaml` |
| `--db` | string | default | Path to evidence database |
| `--session` | string | latest | Scope to a specific session ID |
| `--latest` / `--all` | flag | `--latest` | Use latest session (default) or all sessions |

## Examples

**Basic status (no evaluations yet)**
```bash
ancilis status
```

```
Ancilis — my-agent
  Mode: audit
  Controls: 39 active, not yet evaluated
  No evaluations recorded yet. Run your agent with Ancilis to start collecting evidence.
```

**Status after evidence collection**
```bash
ancilis status
```

```
Ancilis — my-agent
  Mode: audit
  Controls: 39 active, 9 runtime-verified, 27 pending, 1 flagged, 2 failing
  Financial Services (GLBA, SOX, DORA): active — triggered by financial_records declaration
  SOC 2 Type II: active — triggered by financial_records declaration
  Tool calls: 246 evaluated, 0 blocked
  Sync: 246 pending, 0 failed
```

The headline distinguishes runtime-verified controls from attestation-pending,
flagged, and failing ones — it never collapses them into "all passing" while
any control is pending, flagged, or failing. (SOC 2 and the financial overlay
are activated by the `financial_records` data declaration, not by a
`certification_targets` value.)

**Verbose — per-control breakdown**
```bash
ancilis status --verbose
```

```
Ancilis — my-agent
  Mode: audit
  Controls: 39 active, 9 runtime-verified, 27 pending, 1 flagged, 2 failing
  Financial Services (GLBA, SOX, DORA): active — triggered by financial_records declaration
  SOC 2 Type II: active — triggered by financial_records declaration
  Tool calls: 246 evaluated, 0 blocked
  Sync: 246 pending, 0 failed

  Controls:
    ✓ Action Authorization — passing
    ✓ Data Exposure Prevention — passing
    ✗ Tool/Model Integrity and Provenance — failing (3 failures)
    ! Audit Trail Completeness — flagged (3 flags)
    ○ Agent Identity and Authentication — pending (attestation required)
    ○ Human Oversight and Decision Accountability — pending (attestation required)
    … (39 controls total — 9 runtime-verified, 27 pending, 1 flagged, 2 failing)

  Activation:
    Financial Services (GLBA, SOX, DORA) overlay active — triggered by financial_records declaration
    SOC 2 Type II overlay active — triggered by financial_records declaration

  Evidence records: 246 stored, hash chain legacy-unverified (set ANCILIS_CHAIN_KEY)
```

Per-control markers: `✓` runtime-verified passing · `○` pending (attestation
required) · `!` flagged for review · `✗` failing · `–` not yet evaluated. A
flagged or pending control is never shown as passing.

**Verbose with flagged control warnings**
```bash
ancilis status --verbose
```

```
  Warnings:
    [scope confinement] Scope Confinement flagged deviations
            Review recent activity: ancilis report --period 1d
```

**Scope to a specific session**
```bash
ancilis status --session sess_20260412_abc123 --verbose
```

## Status Indicators

| Indicator | Meaning |
|-----------|---------|
| `not yet evaluated` | No evidence collected yet |
| `N runtime-verified` | Controls with a runtime evaluator that passed |
| `N pending` | Controls awaiting attestation, or not yet evaluated |
| `N flagged` | Controls with a deviation to review (e.g. sensitive data with no destination policy) |
| `N failing` | Controls with a failure |
| `— all passing` | Appended only when nothing is pending, flagged, or failing |

## Overlay Trigger Line

When an overlay is active via automatic data classification, the status line shows what triggered it:

```
  SOC 2 Type II: active — triggered by financial_records declaration
```

This confirms that your `ancilis.yaml` data classification caused the overlay to activate, rather than an explicit configuration.

## Common Errors

| Error | Fix |
|-------|-----|
| `Error loading config` | Run `ancilis init` to create `ancilis.yaml` |
| `No evaluations recorded yet` | Attach Ancilis middleware to your agent and run it |
