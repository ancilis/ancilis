The candidate contains 41 AKSI controls, 37 overlays and two certification
profiles. These are configuration and evidence crosswalks. A framework ID,
activated control or passing SDK result does not establish legal applicability,
complete framework coverage or certification.

The SDK freezes AKSI v0.6 to framework source commit
`aeda1839054090a8384f3d9d2700a656fab519a2`, recorded in `shared/aksi_version.json`.
That provenance identifies the catalog used by this candidate; it does not
establish that every external framework reference remains current.

## How to interpret support

| Evidence route | What it provides | What remains separate |
|---|---|---|
| Direct runtime evaluator | A result from the inputs available to the configured legacy engine | Correct instrumentation, input completeness, organizational scope and requirement conformance |
| Stored manual attestation in Python | A local claim with required-field, freshness and revocation checks | Independent issuer authentication and proof that the stated process occurred |
| Caller manual attestation in TypeScript | An accepted action-level assertion | Required-field, freshness, revocation and issuer checks |
| Framework mapping | A catalog association between an AKSI control and a requirement reference | Current normative validation, applicability and complete coverage |
| Native episode capture | Observations, revisions, relationships and explicit coverage gaps | Automatic enforcement or proof of control operation |
| Organizational action | A documented external process, decision or assessment | Execution and approval by the responsible organization |

Python has 18 direct evaluators and 23 stored attestation routes; TypeScript has
14 direct evaluators and 27 caller-attestation fallbacks. Several direct
evaluators also have different meanings under the same IDs. See the
[TypeScript capability differences](/sdk/typescript#control-parity-with-the-python-sdk).
Do not count a fallback or a shared catalog entry as a direct evaluator.

Existing JSON assets preserve historical references for compatibility. Their
descriptions, dates and mappings must not be interpreted as overriding the
limitations above. Data-classification triggers identify candidate evidence
scope; they do not determine regulated status, jurisdiction, provider role,
device clearance, authorization or certification.

Agent libraries, MCP attachment and telemetry formats are integration surfaces,
not additional regulatory frameworks. Adding a producer does not add a
normative crosswalk or establish that every required field is available.
