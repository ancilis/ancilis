## Overview

This regime combines FDA's PCCP framework for AI-enabled medical device software (final guidance 2025-08-18, three components: Description of Modifications, Modification Protocol, Impact Assessment) with statutory premarket cybersecurity for 'cyber devices' under FD&C Act sec. 524B (effective 2023-03-29) and its implementing Premarket Cybersecurity Guidance (final 2025-06-27), plus the AI-Enabled Device Software Functions lifecycle/transparency draft guidance (2025-01-07). It is a total-product-lifecycle regulatory regime, not a pure security standard; AKSI maps strongly to its postmarket cybersecurity expectations.

The `fda_ai_device_pccp` overlay packages AKSI control coverage for this regime, mapping each AKSI control to the relevant 524B statutory provisions, PCCP components, premarket cybersecurity guidance sections, and the AI-Enabled Device Software Functions lifecycle draft guidance.

**Use this overlay when your agent:**
- Is or supports an AI/ML-enabled medical device software function regulated by FDA / CDRH
- Falls within the FD&C Act sec. 524B definition of a 'cyber device'
- Operates under a Predetermined Change Control Plan (PCCP) for permitted modifications
- Is part of a system seeking or maintaining an FDA premarket submission with cybersecurity content
- Requires total-product-lifecycle (TPLC) performance monitoring and postmarket vulnerability management

<Warning>
This overlay is a **REVIEW-FIRST** mapping, not production-asserted coverage. Most control mappings are marked `partial` and several are `verified=false`. None of the controls in this overlay currently carries runtime evidence requirements (every control's `evidence_requirements` list is empty), so coverage should be treated as **indicative** and validated against your device's regulatory submission before relying on it.
</Warning>

---

## Activation

Enable the overlay explicitly in your configuration:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - fda_ai_device_pccp
```

This overlay uses a `certification` trigger type, so it activates explicitly via configuration rather than auto-activating on declared data handling.

## Jurisdiction & Retention

**Jurisdiction:** United States (FDA / HHS; FDA Center for Devices and Radiological Health).

No `evidence_retention_minimum_days` is defined for this overlay; retention is governed by your device's applicable FDA recordkeeping and Medical Device Reporting (21 CFR 803) obligations.
