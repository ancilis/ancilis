## Overview

The `eu_gpai_code` overlay associates AKSI controls with the EU General-Purpose AI (GPAI) Code of Practice. It is a scaffold mapping created to resolve a dangling control-to-overlay reference: it wires the 39 AKSI controls that reference this overlay but does not yet assert any framework requirement mappings.

Per the overlay definition: *"SCAFFOLD overlay for 'eu_gpai_code' — created to resolve a dangling control->overlay reference (D3). No aksi-ultra research crosswalk exists for this id; control wiring only, no requirement-ID mappings asserted."*

<Warning>
This overlay is a **scaffold mapping** and is **not yet backed by runtime evidence**. The top-level `scaffold` flag is set and the `framework_mapping` is empty, so no requirement-ID crosswalk has been asserted (verified=false by construction). Treat any coverage shown here as **indicative only**. Framework references and evidence requirements must be populated from an authoritative source before any production assertion.
</Warning>

**Use this overlay when your agent:**
- Is a general-purpose AI system in scope of the EU GPAI Code of Practice
- Declares that it handles AI-classified data (`DC-AI`)
- Needs the GPAI control set wired ahead of an authoritative requirement crosswalk

---

## Activation

Activate explicitly in your config:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - eu_gpai_code
```

**Data classification trigger** — because this overlay uses a `data_classification` trigger, it also auto-activates when your agent declares (via `my_agent_handles`) that it handles the data class `DC-AI`. See [Data Classification](/data-classification) for how to declare handled data classes.
