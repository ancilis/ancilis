## Overview

HITRUST CSF v11.8.0 (current as of mid-2026) is a prescriptive, certifiable security/privacy control framework; its AI Security Assessment and Certification (introduced v11.4.0, available as `ai1` paired with `e1`/`i1` or `ai2` paired with `r2`) adds up to 44 curated AI-specific requirement statements across 12 topic categories, harmonized to NIST, ISO, OWASP LLM Top 10 2025, and MITRE ATLAS mitigations, and requires the in-scope AI system to be in production deployment. AKSI maps strongly to the runtime-facing categories (access, logging/monitoring, filtering/sanitizing inputs-outputs, model robustness).

The `hitrust_ai_security` overlay packages AKSI control evidence against the AI Security Assessment categories, binding each AKSI control to one or more `AISec.*` requirement categories so that runtime agent posture can be presented against the certification's AI-specific requirement statements.

<Warning>
This overlay is a scaffold mapping that is not yet backed by runtime evidence — treat coverage as indicative only. Every control in the source mapping carries `verified: false` and no evidence requirements, and most category mappings are marked partial coverage. Per the source crosswalk, this is REVIEW-FIRST, not production-asserted (confidence: medium).
</Warning>

**Use this overlay when your agent:**
- Is an in-scope AI system in production deployment pursuing or maintaining a HITRUST AI Security Assessment and Certification (`ai1`/`ai2`)
- Handles AI-classified data (`DC-AI`)
- Handles protected health information (`DC-PHI`)
- Must demonstrate runtime posture against the HITRUST AI Security categories (access, logging/monitoring, input/output filtering, model robustness)

---

## Activation

This overlay is a `certification` trigger and is activated explicitly:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - hitrust_ai_security
```
