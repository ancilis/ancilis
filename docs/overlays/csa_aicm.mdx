## Overview

The CSA AI Controls Matrix (AICM v1.0, released 2025-07-10) is an industry-consensus AI control framework with 243 control objectives across 18 domains — 17 carried from the CSA Cloud Controls Matrix (CCM v4) plus a new AI-specific Model Security (MDS) domain of 13 controls. It ships with an AI-CAIQ, implementation and auditing guidelines, and mappings to ISO 42001, ISO 27001, NIST AI RMF, BSI AIC4 and the EU AI Act.

The `csa_aicm` overlay packages AKSI control evidence against AICM/CCM control objectives. It maps each AKSI control to the AICM/CCM controls it covers at the runtime/inference-time slice (agent identity, action authorization, data handling, monitoring and response). Coverage is recorded per control as `partial` or `inherited` — the overlay claims only the agent-runtime portion of each framework objective, with org-wide program elements treated as inherited from the surrounding ISO 27001 / SOC 2 / governance program.

<Warning>
This overlay is a review-first scaffold mapping that is not yet backed by runtime evidence. Every control carries `verified: false` and no evidence requirements are populated in the source overlay definition. Treat the coverage shown below as indicative of intended framework alignment, not as production-asserted compliance.
</Warning>

**Use this overlay when your agent:**
- Operates under a CSA AICM / CCM-aligned AI governance program
- Needs to demonstrate agent-runtime coverage of AICM control objectives (Model Security, Agent Security Boundaries, Agent Access Restriction, etc.)
- Maps to adjacent frameworks (ISO 42001, ISO 27001, NIST AI RMF 1.0, BSI AIC4, EU AI Act) and wants a consensus crosswalk
- Is subject to AI supply-chain, transparency and accountability (STA) obligations

---

## Activation

Activate the overlay explicitly in your project configuration:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - csa_aicm
```

This overlay has trigger type `always_on` (triggered by data class `DC-AI`): once enabled, it applies to every governed action of the agent rather than activating only on a specific declared data flow.

## Retention & Jurisdiction

**Jurisdiction:** International (industry consensus standard; maps to ISO 42001, ISO 27001, NIST AI RMF 1.0, BSI AIC4, EU AI Act). AICM is a consensus control framework rather than a single-jurisdiction legal regime, so retention and notification obligations are inherited from the adjacent frameworks and contracts your program is bound to rather than fixed by this overlay.

**Evidence retention:** The overlay definition does not set an evidence retention minimum; retention is governed by your surrounding compliance program and any mapped regulatory obligations.

**Regime version:** AICM v1.0 (released 2025-07-10; controls/guidance refreshed through late 2025), built on CCM v4.0.
