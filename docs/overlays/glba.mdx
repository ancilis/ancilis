## Overview

The `glba` overlay is a financial services overlay for agents handling customer financial data, transaction records, or financial reporting information. It packages evidence for GLBA Safeguards Rule controls, SOX internal-control obligations, and DORA operational resilience requirements.

Rather than a single-regulation attestation, this overlay treats financial-services handling as a combined control package: the GLBA Safeguards Rule drives customer-information security controls, SOX drives internal-control and record-retention rigor for financially relevant systems, and DORA adds ICT resilience and incident-management expectations for regulated financial entities.

**Use this overlay when your agent:**
- Handles customer financial data
- Processes transaction records
- Works with financial reporting information
- Operates within a business subject to GLBA, SOX, or DORA obligations

---

## Activation

Activate the overlay explicitly in your agent configuration:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - glba
```

**Data classification trigger** — because this overlay uses a `data_classification` trigger, it also auto-activates when your agent declares that it handles the relevant financial data classification (`DC-FIN`) via `my_agent_handles`:

```yaml
my_agent_handles:
  - DC-FIN
```

See [Data Classification](/data-classification) for how declared data types map to overlay activation.

## Retention & Jurisdiction

- **Jurisdiction:** `us-eu` — GLBA and SOX apply to US financial-services obligations, while DORA adds EU ICT operational-resilience expectations for regulated financial entities.
- **Evidence retention minimum:** 2555 days (7 years), aligned with SOX §802 recordkeeping obligations for financially relevant systems.
