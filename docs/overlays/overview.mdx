## What Are Overlays?

Overlays are compliance framework extensions that map AKSI controls to the specific evidence requirements of a regulatory or certification framework. When an overlay is active, each control evaluation produces evidence tagged to the overlay's requirements — enabling framework-specific posture reporting and audit packages.

Ancilis ships with overlays for the most common frameworks affecting AI agents:

| Overlay ID | Framework | Best For |
|-----------|-----------|----------|
| `glba` | GLBA / SOX / DORA | Financial services agents handling customer data |
| `fedramp` | FedRAMP Moderate | US federal cloud and government agents |
| `ccpa` | CCPA / CPRA | Agents operating in California / handling US consumer data |
| `nist-csf` | NIST Cybersecurity Framework | Enterprise risk and security programs |
| `soc2` | SOC 2 Type II | SaaS and cloud service providers |
| `gdpr` | EU GDPR | Agents processing EU personal data |
| `hipaa` | HIPAA | Healthcare and health data agents |
| `iso-42001` | ISO/IEC 42001 | AI management system certification |
| `eu-ai-act` | EU AI Act | Agents deployed in the EU |
| `pci-dss-v4` | PCI DSS v4.0 | Payment card and financial transaction agents |
| `cmmc-l2` | CMMC Level 2 | US defense industrial base contractors |

## How Activation Works

Overlays can be activated three ways:

### 1. Explicit activation in `ancilis.yaml`

```yaml
compliance:
  overlays:
    - glba
    - nist-csf
```

### 2. Certification-driven activation

When you set a `certification_targets` entry, Ancilis automatically activates the
overlay(s) and extension controls required by that certification. Valid targets
include `aiuc-1` and `gov-contractor` (framework overlays such as `soc2` are
activated from `my_agent_handles` data declarations, not here):

```yaml
certification_targets:
  - aiuc-1
```

### 3. Automatic data classification trigger

When your agent processes data classified under specific data types (e.g. `financial_data`, `personal_info`), the `ActivationResolver` automatically activates the matching overlay without any config change. This appears in `ancilis status` as:

```
Financial Services (GLBA, SOX, DORA): active — triggered by financial_records declaration
```

## Control Mapping

AKSI controls are universal; overlays add framework-specific evidence requirements on top of each control:

| AKSI Control | What It Measures | Overlay Enhancement |
|-------------|-----------------|---------------------|
| PR-01 | Action authorization | Maps to GLBA 314.4(a), FedRAMP AC-2, NIST CSF PR.AC |
| PR-02 | Permission scope enforcement | Maps to PCI DSS 1.3, CMMC AC.2.006, GLBA 314.4(c) |
| PR-03 | Tool/model integrity & provenance | Maps to SOC 2 CC7.1, FedRAMP SI-3, NIST CSF DE.CM |
| PR-04 | Data exposure prevention | Maps to GDPR Art.32, HIPAA 164.312, CCPA 1798.150 |
| PR-06 | Audit trail completeness | Maps to SOX §302/§404, GLBA 314.4(h), FedRAMP AU-2 |
| ID-04 | Supply chain & dependency risk | Maps to NIST CSF ID.RA, DORA Art.9, PCI DSS 6.3 |

## Reading Posture Output With an Overlay Active

When an overlay is active, `ancilis report` includes framework-specific sections:

```
Ancilis Posture Report — my-agent
Period: 2026-05-08 to 2026-06-07
Mode: audit
Posture: HEALTHY (1/39 controls passing)
Evaluations: 16 total | 0 blocked | 16 allowed
Active overlays: Financial Services (GLBA, SOX, DORA), SOC 2 Type II
Active certifications: none
Evidence chain: ✓ legacy-unverified (set ANCILIS_CHAIN_KEY) (16 records)

Baseline Controls:
  ✓ 1 controls passing (full detail preserved in markdown)
Tools evaluated: dependency-scanner

Compliance Matrix:
  Control | Financial Services (GLBA, SOX, DORA) | SOC 2 Type II
  DE-01   | ✓                                    | ✓
  DE-02   | -                                    | -
  DE-03   | -                                    | -
  # ... 36 more control rows (DE-04 … RS-06), one per AKSI control ...
  RS-06   | -                                    | -
```
