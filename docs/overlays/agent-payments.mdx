## Overview

The `agent-payments` overlay packages AKSI control wiring for AI agents that initiate, authorize, or otherwise handle payment data. It groups the AKSI governance, identity, protection, detection, response, recovery, and payment-specific controls that apply when an agent works with payment information so that posture can be tracked against a single overlay.

<Warning>
This overlay is a **scaffold mapping**. It wires the controls that reference `agent-payments` but does not yet assert any framework requirement mappings — its `framework_mapping` is empty and it is flagged `scaffold: true`. Treat coverage as indicative only; controls are not yet backed by runtime evidence. Populate framework references and evidence requirements from an authoritative source before relying on this overlay for any production assertion.
</Warning>

**Use this overlay when your agent:**
- Initiates, authorizes, or settles payments
- Handles payment data classified as `DC-PAY`
- Stores, transmits, or processes payment instrument details
- Operates within a workflow subject to payment-handling controls

---

## Activation

Activate the overlay explicitly in your config:

```yaml
# ancilis.yaml
compliance:
  overlays:
    - agent-payments
```

**Data classification trigger** — because this overlay's `trigger_type` is `data_classification`, it also auto-activates when your agent declares that it handles the relevant payment data classification (`DC-PAY`) via `my_agent_handles`. See [Data Classification](/data-classification) for how to declare handled data classes.
