## Overview

When a compliance overlay is active, `ancilis report` produces richer output that links each control to the relevant framework requirements. This guide walks through how to read every section.

---

## Report Header

The `terminal` format prints the header as a set of separate lines:

```
Ancilis Posture Report — my-agent
Period: 2026-05-08 to 2026-06-07
Mode: audit
Posture: HEALTHY (1/39 controls passing)
Evaluations: 16 total | 0 blocked | 16 allowed
Active overlays: Financial Services (GLBA, SOX, DORA), SOC 2 Type II
Active certifications: none
Evidence chain: ✓ legacy-unverified (set ANCILIS_CHAIN_KEY) (16 records)
```

| Field | Meaning |
|-------|---------|
| **Agent** | The `agent.name` from `ancilis.yaml` (shown after the em dash in the title) |
| **Period** | Evidence window passed to `--period` (default 30d), shown as a start-to-end date range |
| **Mode** | `audit` (log only) or `enforce` (block on failure) |
| **Posture** | Overall posture plus the count of passing controls |
| **Evaluations** | Total / blocked / allowed evaluation counts for the period |
| **Active overlays** | Active overlay(s) — the framework name, not the ID |
| **Evidence chain** | Hash-chain status and the number of evidence records |

---

## Compliance Matrix (terminal)

In the `terminal` format, controls are shown as a matrix keyed by AKSI control ID, with one column per active overlay:

```
Compliance Matrix:
  Control | Financial Services (GLBA, SOX, DORA) | SOC 2 Type II
  DE-01   | ✓                                    | ✓            
  DE-02   | -                                    | -            
  DE-03   | -                                    | -            
  ...
  PR-03   | -                                    | -            
  ...
```
<!-- truncated: the matrix lists all 39 AKSI controls (DE-*, GOV-*, ID-*, PR-*, RC-*, RS-*) -->

### Matrix cells

| Cell | Meaning |
|------|---------|
| `✓` | At least one evaluation in the period and no failures |
| `✗(n)` | `n` failed evaluations for this control under that overlay |
| `-` | No evidence collected for this control in the period |

## Control Tables (markdown)

The `markdown` format expands the matrix into tables. The **Baseline Security** section uses the columns `Control | Pass Rate | Evaluations | Status`:

```
| Control | Pass Rate | Evaluations | Status |
|---------|-----------|-------------|--------|
| Behavioral Anomaly Detection | 0.0% | 16 | Pass |
| Classification Drift and Boundary Validation | - | 0 | No data |
| Tool/Model Integrity and Provenance | - | 0 | No data |
```
<!-- truncated: the baseline table lists all 39 controls by display name -->

Each per-overlay section uses the columns `Citation | Control | Type | Evaluations | Pass Rate`, keyed by control ID:

```
| Citation | Control | Type | Evaluations | Pass Rate |
|----------|---------|------|-------------|-----------|
| GLBA 16 CFR 314.4(c)(8), 314.4(h), SOX §404, DORA Art.10, Art.17, Art.19 | DE-01 | runtime | 16 | 0.0% |
| GLBA 16 CFR 314.4(c)(4), 314.4(c)(7), SOX §404, DORA Art.28 | PR-03 | runtime | 0 | - |
```
<!-- truncated: each overlay section lists all its mapped controls -->

### Status values

| Value | Meaning |
|-------|---------|
| `Pass` | At least one evaluation in the period and no failures |
| `{n} failures` | `n` failed evaluations for this control |
| `No data` | No evidence collected for this control in the period |

### Columns

| Column | Description |
|--------|-------------|
| **Control** | In the baseline table, the AKSI control display name; in overlay tables, the AKSI control ID |
| **Citation** | Overlay-specific regulatory citations for the control |
| **Type** | `runtime` (Ancilis evaluates it from evidence) or `attestation` (organizational control, evidenced by attestation) |
| **Pass Rate** | Share of passing evaluations; `-` means no evidence |
| **Evaluations** | Total evaluation count for the period |
| **Status** | Per-control status for the period (baseline table only) |

## Flags vs Failures

**Failures** mean the control evaluation returned `FAIL` or `ERROR`. They surface as `✗(n)` in the terminal Compliance Matrix and as `{n} failures` in the markdown Status column:
- In `audit` mode: logged, no blocking
- In `enforce` mode: the tool call was blocked

**Flags** (`FLAG`) mean a deviation was detected that does not directly fail the control (it is counted separately from failures):
- Example: a tool call to an unusual destination that was allowed, but noted for review
- Always investigate flags — they can be early signals of control drift

## Posture Summary

The terminal header carries the posture line, with the count of passing controls:

```
Posture: HEALTHY (1/39 controls passing)
```

| Posture | Meaning |
|---------|---------|
| `HEALTHY` | No controls require attention; evidence chain valid |
| `ATTENTION` | One or two controls have failures or fall below threshold |
| `CRITICAL` | Three or more controls require attention, or the evidence chain is broken |

## Per-Overlay Compliance Posture

When an overlay is active, the `markdown` report appends one section per overlay (for example, `## Financial Services (GLBA, SOX, DORA) Compliance Posture`). Each section states what activated the overlay, which controls sit at the strict threshold, and how many mapped criteria Ancilis evaluates at runtime versus by attestation, followed by the control table:

```
## Financial Services (GLBA, SOX, DORA) Compliance Posture

**Activated by:** financial_records declaration  
**Controls at strict threshold:** DE-01, PR-01, PR-02, PR-04, PR-05  

Ancilis provides runtime evidence for 18 of 39 mapped criteria; the remaining 21 are organizational controls it does not assess (evidenced by attestation).

| Citation | Control | Type | Evaluations | Pass Rate |
|----------|---------|------|-------------|-----------|
| GLBA 16 CFR 314.4(c)(8), 314.4(h), SOX §404, DORA Art.10, Art.17, Art.19 | DE-01 | runtime | 16 | 0.0% |
| GLBA 16 CFR 314.4(c)(4), 314.4(c)(7), SOX §404, DORA Art.28 | PR-03 | runtime | 0 | - |

Evidence retention: 2555 days configured, 2555 required ✓
Enforce the window with: ancilis evidence prune
```
<!-- truncated: each overlay section lists every mapped control by ID with its regulatory citation -->

The `Citation` column maps each control back to specific regulatory sections, making it easy to identify which framework obligations have open findings.

## Investigating a Failure

When you see `✗(n)` on a control in the Compliance Matrix (or `{n} failures` in the markdown Status column):

**Step 1 — Get NDJSON evidence**

Each NDJSON line is an evidence record; per-control results are nested under `control_results`:
```bash
ancilis report --format ndjson --period 30d | jq 'select(.control_results[].control_id == "PR-03")'
```

**Step 2 — Filter to failures**
```bash
ancilis report --format ndjson | jq 'select(.control_results[] | .control_id == "PR-03" and .result == "FAIL")'
```

**Step 3 — Review the detail and evidence fields**
```json
{
  "tool_name": "delete_production_db",
  "decision": "BLOCK",
  "mode": "enforce",
  "timestamp": "2026-04-12T09:43:12Z",
  "control_results": [
    {
      "control_id": "PR-03",
      "control_name": "Tool Provenance Verification",
      "result": "FAIL",
      "detail": "Tool 'delete_production_db' is not registered.",
      "evidence_data": {}
    }
  ]
}
```

**Step 4 — Approve the tool or update scope**
```bash
ancilis approve-tool delete_production_db  # if the tool should be allowed
# or update ancilis.yaml to add it to security.tools.allowed
```

## Session-Scoped Reports

By default `ancilis report` shows the latest session (`--latest`); pass `--all` to span every session. Use `--session <id>` to scope the report to one specific session.

The session ID is not printed in the terminal or markdown header — read it from the `session_id` field of any NDJSON evidence record:

```bash
# Get a session ID from the NDJSON evidence stream
ancilis report --format ndjson | jq -r '.session_id' | head -1
# 68a36bf9-fc42-4598-9b15-4a0b399233d3

# Scope a report to that exact session
ancilis report --session 68a36bf9-fc42-4598-9b15-4a0b399233d3 --format markdown --output audit-package.md
```

## Export Formats for Auditors

| Format | Command | Best For |
|--------|---------|----------|
| PDF | `ancilis report --format pdf --output report.pdf` | Formal audit packages |
| Markdown | `ancilis report --format markdown --output report.md` | Pull request evidence |
| CSV | `ancilis report --format csv --output evidence.csv` | Spreadsheet review |
| NDJSON | `ancilis report --format ndjson` | SIEM / log pipeline ingestion |
| AIUC-1 Readiness | `ancilis report --format aiuc1-readiness` | AIUC-1 certification prep |
| OSCAL | `ancilis report --format oscal` | GRC tooling / OSCAL ingestion |
